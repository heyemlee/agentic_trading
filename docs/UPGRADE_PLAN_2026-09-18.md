# 升级方案：复用现成能力，完成双账户工作流与四个导航

日期：2026-09-18。状态：已整合四个导航讨论及代码复核修正的计划文档；尚未实施或启用新的实盘权限。

本次交付仅更新本文档。下文描述未来实施范围，不表示已经修改前端、后端、生产配置、交易权限或部署。此前导航草稿与本稿有差异时，以本稿为准。

## 1. 目标与取舍

本项目是个人使用的集成系统。采用现有模型、金融技能、数据工具和券商服务，只维护它们之间缺失的连接。

- **Agentic 账户**：在预先授权的股票／ETF 范围、资金和风险限额内，自动研究、买入、加仓、减仓和清仓；正常订单不要求逐笔人工确认。异常或超出授权时停止相应操作并通知。
- **我的账户（下文也称本账户）**：读取个人账户持仓，完全按需结合个人目标、用钱时间和历史判断提供只读建议；用户自行决定和交易。账户刷新不自动触发 AI 分析，聊天、资料和建议不能产生可执行订单或改变 Agentic 权限。
- 默认延续 Claude Code 订阅运行方式、现有队列、SQLite、Robinhood MCP、服务层和部署方式。新供应商必须能补具体缺口才接入。
- 初版按日／周研究和事件复查设计，不承诺高频交易或全天候即时止损。调度频率是待验证的运行参数。
- 四个主导航保持 Home、Portfolio、Assistant、More。多个页面可以引用同一结果并提供入口，但不分别维护账户数据、研究报告、权限规则或审计记录。

采用外部能力的三个条件：能访问、适合后台运行、能减少维护或改善决策。界面里能使用、接口能调用、数据有使用权益，分别核实。

## 4. Anthropic 最小接入试验

本次审阅参考版本为 `anthropics/financial-services@35c80df9f4fb49f7888c681242a690dcde403f24`。实施时记录选定版本、许可证、依赖和修改，不运行自动更新的 latest。

优先级：

1. **thesis-tracker**：第一项试验。输入原投资论点、新事实及账户上下文，输出哪些依据强化／削弱、是否需要重新研究。适合日常复查。
2. **catalyst-calendar**：第二项。辅助整理重要事件，但事件日期必须由已核实数据支撑；模型生成的日期不能直接充当风控事件日历。
3. **earnings-analysis**：有财报事件才使用。原技能面向长篇机构报告，应通过薄适配去掉不需要的篇幅、制图和交付格式要求；没有一致预期数据就不声称 beat/miss。
4. **portfolio-rebalance-review**：本账户按需使用其复查框架。原实现依赖 Orion、Addepar、Envestnet 等，应明确替换为已确认可用的 Robinhood 快照与用户目标；未知税批次不作精确税务结论。

参考源：[论点跟踪](https://github.com/anthropics/financial-services/blob/35c80df9f4fb49f7888c681242a690dcde403f24/plugins/vertical-plugins/equity-research/skills/thesis-tracker/SKILL.md)、[事件日历](https://github.com/anthropics/financial-services/blob/35c80df9f4fb49f7888c681242a690dcde403f24/plugins/vertical-plugins/equity-research/skills/catalyst-calendar/SKILL.md)、[财报分析](https://github.com/anthropics/financial-services/blob/35c80df9f4fb49f7888c681242a690dcde403f24/plugins/vertical-plugins/equity-research/skills/earnings-analysis/SKILL.md)、[组合复查](https://github.com/anthropics/financial-services/blob/35c80df9f4fb49f7888c681242a690dcde403f24/claude-for-financial-advisors/skills/portfolio-rebalance-review/SKILL.md)。

集成方式：

- 新增一个小型研究任务适配层，复用 `ClaudeCodeChatModel`、现有只读 MCP 和持久队列。一次先接一项技能，不创建插件平台。
- 在隔离运行目录提供经审阅的技能，适配现有严格工具配置。禁止运行时下载、安装或更新插件。
- 对外部技能的提问步骤改为明确任务输入；资料不足返回结构化缺失项，不让后台无限等待用户。
- 输出复用已有 evidence 和决策记录，包含账户范围、截至时间、来源、主要变化、反证及缺失信息；需要交易建议时再适配 `ConservativeProposal` 和相应入场／退出条件。轻量论点检查只产生复查结论，个人组合复查只产生只读建议，不把每项技能输出都变成可执行提案。
- 研究产物的账号和用途由服务端绑定，不能信任模型自报。共享同一时点的公共公司事实，账户建议与记忆分别隔离。
- TradingAgents 仍是 pinned dependency，不修改、不 vendoring。新技能只替换证明确有收益的任务；不让每个技能再启动一整套重复的多 Agent 研究。
- 路线选择先使用明确的任务映射，不建立多供应商动态路由平台。首项技能未通过试验前，保留既有研究路线；财报、事件和组合复查技能逐项验证，OpenAI 接入不阻塞导航升级。
- 不使用 Anthropic Managed Agents 的 API key 路线；维持仓库规定的 Claude Code 订阅路径。

试验建议使用固定的 20 个股票／ETF 案例，其中包含数据缺失、来源冲突、过期消息和论点破坏。相同输入／时间截点分别运行现有路线与新技能。比较事实错误、证据完整性、格式通过率、人工修改量、耗时和额度占用。20 个案例用于集成筛选，不用于证明投资收益。

通过条件：关键事实可核查、不出现账户串用或订单工具访问，质量不劣于基线且减少维护／耗时／人工修订中的至少一项。不通过就保留旧路线，不以接入成功作为业务成功。

## 5. Agentic 自主交易升级

### 5.1 使用现有链路

```text
实际持仓 + 自选／筛选结果 + 已核实事件
                    ↓
现有 schedule / triggers / research_jobs：挑选需要复查的对象
                    ↓
选定研究技能或 TradingAgents → 现有 policy / evidence / Hard Risk
                    ↓
授权范围内自动批准 → service/approvals.py → execution.py
                    ↓
Robinhood 官方 MCP → 成交对账 → 记录、评估、通知
```

模型提议，代码按预先授权执行。正常 BUY／ADD／REDUCE／SELL 在授权内无需每笔确认；超出范围或状态不明时拒绝执行／升级人工。该工作流不改变本账户只读权限。

升级人工不代表可以点击批准绕过硬限制。只有规则允许人工处理的提案进入审批；需要调整权限或限额时，仍走现有配置审阅与生效流程。正常自主提案等待系统处理时，不显示成“等待你批准”。

### 5.2 补齐持续研究，而非重复行情产品

- 显式调度 `micro_live`，从其真实持仓与有限候选池选题；不要沿用 core 默认标的冒充 Agentic 维护。
- Robinhood 自选／筛选器提供候选来源，不授予自动买入权限；最终新增风险动作仍受授权资产范围约束。已持有但移出开仓候选范围的标的仍须能够复查，退出权限单独判断。
- 复用现有持久队列和交易日历，按风险与事件排序；先复查已有风险，再考虑新仓。
- 建议初版每天做一次轻量持仓／事件复查，每周复查候选；重要事件在已核实数据到达时触发。是否增加盘中检查由实际延迟和调用预算决定。
- 轻量检查不等于每个代码跑完整研究。没有实质变化时重用尚有效的事实；命中变化才提交研究。
- 为退出／异常复查预留研究容量，避免本账户聊天或候选研究耗尽 Agentic 维护额度。额度耗尽不得通过增加并发绕过订阅限制。
- 没有官方事件回调时，采用有界的定时读取，不解析手机通知、不把 Cortex UI 抓取作为核心依赖。
- `schedule` 的周期去重需包含账户和任务类型，防止一个账户的研究把另一个标记为已运行；研究与提案均须去重。

### 5.3 统一授权并补齐全量退出

先为现有配置生成一份“有效权限”结果，统一供设置页、预检、风控和自动批准使用。逐项处理当前 stage、micro-live 预检、bucket 开关和永久人工审批标签之间的关系；不能靠提高 stage 或删除 PF04 绕过限制。

同一授权需要明确：指定 Agentic 账户、资产／策略范围、总资金上限、自动可用资金份额、单笔与单股限制、交易次数、现金约束、回撤／日亏损限制、运行时段和停止条件。沿用现有限额作为草案；模型不能修改它们，计划也不自动扩大额度。

BUY、ADD、REDUCE、SELL 分别建模。特别是完整清仓：

- SELL 有独立授权及可卖数量验证，走同一执行入口；不能靠反复 REDUCE 绕过清仓权限。
- 基于已核实持仓、未完成订单及公司行动调整，处理部分成交、撤单、重启恢复；不能超卖。
- 下单前重读报价、账户和授权版本；研究结束后撤销的授权必须立即生效。
- 开仓的事件黑窗和风险限制不机械复制到退出动作；退出仍须通过必要的账户、报价和订单检查。
- 模型 confidence 沿用内部指标语义，不解释为胜率；校验缺失值与阈值，不以高分替代事实证据。

### 5.4 无人值守运行与回退

先验证当前 Mac 的唤醒、网络、Claude 登录、配额、OAuth、任务恢复和通知。只有这些无法满足目标时，才单独评估迁移运行环境。

- 券商或账户状态不明时停止新订单，继续可用的只读恢复与通知。
- Claude 不可用时暂停新研究／新决策；成交对账和已有确定性保护不依赖新模型调用。
- 报价不新鲜或订单结果不明时不凭缓存重下单。
- 本机离线就无法执行本地检查。券商侧保护单须先核实当前官方工具和账户是否支持，不能承诺本地程序提供全天候保护。
- 回退时先撤销自主授权、停止产生新订单，保留对账恢复；未完成订单按其状态处理，代码回滚不代表订单已撤销。

## 6. 本账户助手与 Robinhood 的分工

保留现有只读快照、个人资料、聊天和研究记录。界面重点回答：

1. 我的现有持仓中，哪几个值得现在复查，为什么？
2. 和上次判断相比，哪些事实变了，原来的持仓理由还成立吗？
3. 在我的目标、现金需求和集中度约束下，继续持有／增减仓／不动作分别有什么依据？

这些建议由用户决定；不给本账户创建可批准订单。Agentic 的系统风险预算与本账户建议分别展示，不混用资金。

个人分析完全按需：用户发送问题、点击“复查我的账户”或明确发起标的研究后才调用模型。打开页面、切换标签、读取历史或刷新账户快照不启动 AI 分析，也不设置个人账户的周期研究或自动事件监测。

组合复查先生成最多三项优先事项，给出继续持有、考虑增减、等待证据或需要完整研究等建议及理由。它复用持仓快照、已确认个人目标与有效研究，不为每个持仓自动启动完整多 Agent 分析。没有复查显示空状态；旧结果标注快照和分析时间，刷新持仓不会使旧建议自动变新。

“我的账户”可汇总多个非 Agentic 个人账户，也可限定具体账户。个人资料中的目标、期限和风险偏好需区分用户确认值与配置建议默认值；不能将未确认的配置或 Agentic 实验限额当作个人事实。相同公司的有效公开事实可以复用，账户建议和对话语境分别保存。

不继续开发通用行情终端、全市场筛选器、普通价格提醒、重复的组合涨跌日报、税表、机构客户材料。已有 UI 先减少重复入口与内容，待替代能力确认后再删代码，避免删掉仍被决策链路需要的数据展示。

Robinhood 交易记录保留为成交事实来源；本项目保留“为什么做、为什么没做、触发了什么规则”。需要的报价读取、执行记录和对账即使与券商界面有相同数字，也不是可删的重复功能。

## 7. 最小数据与证据升级

扩展现有 evidence，不新建独立金融数据仓库：

- 影响决策的关键事实关联来源、原文位置、报告期、发布时间／事件时间、读取时间。
- 数字带单位、币种、期间和调整口径；简单计算由代码执行。
- 来源不一致时保留冲突，不让多个模型投票把事实变成真。
- 关键证据缺失：本账户明确标注建议限制；Agentic 的相关新增风险动作不执行。缺某项分析不自动意味着应卖出。
- 已知可靠数据优先；只有现有来源持续造成具体决策缺口时，才试用一个付费来源。金融技能、数据订阅和模型调用的费用分别核实。

研究技能仅能写研究工件，不能改 `config/`、交易账本、授权或 broker 凭证。外部内容始终作为数据处理。

## 8. 四个导航与功能归属

### 8.1 共同规则与默认入口

| 主导航 | 核心问题 | 负责内容 | 普通入口默认 |
| --- | --- | --- | --- |
| Home | 系统在做什么，需要我处理什么？ | 自动化状态、有效待办、最近变化 | Agentic 状态 |
| Portfolio | 我持有什么，这些持仓现在怎样？ | 资产、持仓、对应分析摘要 | Agentic 账户 |
| Assistant | 为什么这样判断，下一步有哪些选择？ | 账户语境下的对话、按需复查与候选排序 | 我的账户 |
| More | 去哪里查完整记录、调整规则？ | 控制、研究、审计、评估与设置目录 | 三组目录 |

- 账户深链优先于普通入口默认值。从个人持仓打开 Assistant 或 Research，必须保留个人账户与标的；不能因目标页默认 Agentic 而改换语境。
- 公共公司事实可共享；资金、个性化建议、对话和执行权限分别绑定账户。切换标签不把旧对话或尚未完成请求的响应写到另一侧。
- 资产快照时间、报价时间、分析时间与执行状态分别显示。未知数据用缺失说明，不当成零；刷新快照不意味着重做研究。
- 前端只展示服务端事实与有效权限，不用提示词、客户端状态或模型 confidence 决定交易资格。
- 保持现有无构建步骤和无离线缓存的界面架构；离线不重放研究提交、审批或配置写入。界面自有文案走 i18n，API 返回内容按原文展示。

### 8.2 Portfolio：资产与持仓

顶部用“Agentic 账户／我的账户”分段切换，不把两类资产堆在同一个页面，也不合计两类资金。

**Agentic 账户**

- 顶部显示净值、现金与持仓市值；资金和表现区显示净投入、P&L、回报与回撤。成本、收益及净投入必须注明来源和计算口径。
- 当前回报是相对记录投入资金的简单回报，不标作年化或与 Robinhood 同口径。投入记录不完整时明确限制，不伪造完整收益历史。
- 持仓显示数量、价格、市值、权重、成本、未实现盈亏和最近分析摘要。修复 `market_value` 与 `market_value_usd` 的字段不一致。
- 点击持仓打开轻量详情，再进入对应完整研究或执行记录。“建议减仓”与“已成交减仓”分别展示；无分析、证据不足、观望和继续持有分别表达。
- 保留账本确认、刷新和差异分类等资产完整性操作。系统／风险状态只提供一行摘要与入口；权限编辑、订单审计和完整研究留在对应页面。
- Core/Sandbox 不进入主资产视图；内部实验及历史记录保留，不改名为真实资金。

**我的账户**

- 顶部只汇总个人账户；多个账户分别展示卡片。账户总值或覆盖不完整时，汇总标注“已读取部分”，不把缺失金额当零。
- 首期明细限股票、ETF 和现金。账户总值与已列明细存在差异时显示未明细化差额及覆盖提示，不能推断差额一定属于期权或加密资产。
- 显示快照时间、刷新状态和最近的持仓分析摘要。只有切换到此分区或用户显式请求时才触发所需的券商刷新；读取已保存快照可复用既有接口。
- 持仓分析使用只读任务并绑定 `account_id+ticker`；移除跳入通用资金桶研究的入口。分析不足显示“尚未分析”或具体限制，不能补成 HOLD。
- 候选发现留在 Assistant；完整报告留在 Research；不在此重建行情图表、价格提醒或通用组合涨跌摘要。

### 8.3 Home：运行状态与行动事项

移除大号净值、资金／P&L、高水位和详细回撤组件，资产明细统一归 Portfolio。页面顺序为有效待办、自动化状态、最近变化；个人任务事项仅有内容时出现，快捷入口保留 Assistant 与 Portfolio。

**有效待办**

- 顶部突出最高优先级一项，显示“另有 N 项”，可展开其余事项并进入各自处理页；无事时显示“无需处理”。
- 优先处理订单结果不明、对账／账本差异和授权连接失效，其次为风控停机或需手动恢复，再是确实需要人工判断的提案，以及需要干预的研究／后台任务故障。
- 正常自主提案的排队、休市、用户主动暂停和会自行恢复的短暂等待归状态主卡，不一律列为故障。冷静期内的权限放宽显示待生效提示与撤回入口，不冒充必需批准的订单。
- 待办由仍未解决的状态计算，恢复后退出。同一问题不因订单、研究和推送各有记录而重复计数；历史失败不永久挂在首页。
- 请求失败或状态无法读取时显示“无法确认”，不能以空列表推断“无需处理”。

**自动化状态**

- 分别显示研究运行状态、自主交易是否授权及阻断原因；服务 READY 不等于自主交易已开启。
- 显示当前任务、下一次实际计划任务和数据状态，链接 Lab／Research／System。未排期或计划不可读时如实说明。
- 账户核对时间取实际账本核对结果，订单检查时间取订单状态记录；循环心跳只能证明后台运行过，不能显示为“对账成功”。

**最近变化与个人事项**

- 最近变化最多三项，来源为统一审计记录，强调为何行动／观望及执行结果；同一决策的连续状态可合并展示并链接完整 Activity。
- 个人账户仅提示用户已请求任务的完成、失败，以及新分析实际发现的变化。不因快照自然变旧长期占用 Home 待办，也不为生成首页摘要自动调用模型。
- 当前问题、历史事件和推送投递记录分别表达：可以复用来源，不把投递记录当作待办清单。

### 8.4 Assistant：解释与按需分析

顶部明确切换“我的账户／Agentic 账户”。默认我的账户；会话固定所属语境，切换时恢复该侧会话或新建会话，不将同一段历史重新绑定到另一账户。

**我的账户**

- 最近一次主动组合复查最多显示三项优先事项，并注明账户范围、快照时间和分析时间；未复查显示空状态，旧结果提供“重新复查我的账户”。
- Chat 回答持仓风险、历史判断、目标变化与假设情景；可讨论全部个人账户，也可限定具体账户，范围始终可见。
- Discover 读取 Robinhood 自选和已保存筛选器结果，提供个人适合度与研究优先级排序。保留候选来源、分页／截断与不可用提示；不另建全市场扫描或自选管理器。
- 保留输入具体股票／ETF 代码做只读研究的入口；未持有候选允许分析，但不能伪装成该账户已有持仓。没有个人目标或当前数据时说明结论限制。
- 个人资料仅显示摘要与统一编辑页入口，删除聊天内重复编辑器。当前任务显示进度、错误及取消入口，完整研究历史归 Research。
- 删除与 Portfolio 重复的最近持仓结论列表；聊天可以引用原研究，不额外生成另一套持仓报告。

**Agentic 账户**

- 对话解释已记录的买入、卖出、观望、规则阻断和权限，不显示 Discover，不通过聊天修改候选范围、配置或授权。
- 重新研究通过明确操作卡提交绑定 Agentic 账户的任务，说明研究结果可能在既有授权内进入真实执行链；解释问题本身不静默发起研究或下单。
- 复用同一任务队列、额度预留和执行服务；已有有效研究可引用，确需更新再提交，避免多入口启动重复分析。

**外部 AI 与研究路线**

- 不显示 OpenAI／Claude 品牌页或供应商切换器。内部先按任务映射到已经验证的路线，完整结果记录技能／模型版本与证据。
- 轻量复查优先重用有效公共事实与既有研究，完整研究按需发起。个人建议与 Agentic 提案即使使用相同公司事实也分别计算。
- 外部产品报告先经聊天粘贴引用并标记来源与日期，关键交易事实重新核实；本轮不增加文档平台或专用导入中心。

### 8.5 More：控制与完整记录目录

More 顶部保留 System 状态入口，进入原系统页及暂停流程；目录不复制控制开关。分组如下：

| 分组 | 入口与归属 |
| --- | --- |
| Agentic 控制 | 自主权限与限额（进入 Settings 权限区）、Risk、有人工必审事项时才显示的 Approvals |
| 记录与研究 | Research、Activity、Evaluation |
| 账户与偏好 | 我的个人情况、设备与通知、Settings、语言、登录／退出 |

目录仅显示系统状态、风险层级、人工待办数量、运行中研究和对账异常等关键徽标，其余使用静态说明；不建设第二个 Home。

- **System**：服务、连接、排期、后台健康和暂停／恢复；区分停止新订单与继续对账，不能暗示暂停已撤销券商在途订单。
- **自主权限与 Risk**：权限区说明账户、动作、范围、限额、版本和待生效变更，所有编辑留在 Settings；Risk 说明当前风险和规则如何限制动作。二者与执行链共用服务端有效权限，不各自计算是否可交易。
- **Research**：Agentic／我的账户分段切换，从 More 进入默认 Agentic，深链保留原账户和记录。个人范围可按账户筛选；记录显示结果、时间、来源、主要变化、反证和证据限制。完成 Portfolio／Assistant 的替代入口及旧链接迁移后，移除通用 ticker／bucket／trigger 启动表单，后台调度接口继续保留。
- **Research 分数**：移除固定 50 分跨任务门槛图；需要显示内部 confidence 时注明语义，适用阈值来自该任务与授权记录，不解释为胜率或不同路线的统一评分。
- **Lab**：仅从具体研究或 Home 当前任务进入，保留原记录绑定。展示真实参与角色和步骤；轻量技能没有整套多 Agent 过程时使用普通任务过程，不虚构工位、调用或耗时。
- **Activity**：记录研究—提案—订单—成交—对账及权限／暂停变更。金额、成交数量等必要字段继续保留以核对执行；不扩展成 Robinhood 通用订单历史产品。
- **Evaluation**：先统一净值、现金流、研究、提案和成交的账户／研究范围，再提供 Agentic 相对同现金流基准的记录。保留标记明确的历史 Demo 实验，不混入实盘；不能可靠恢复的实盘历史从新起点采样，说明起始日期和数据缺口。
- **研究路线质量**：在 Evaluation 中增加分区，先记录实际可采集的耗时、调用量、失败率、格式与证据检查结果；没有数据就显示未评估。事实准确率、人工修订量等来自第 4 节固定案例审阅，同题同时间截点后才比较，不将自评分当准确率或调用次数当精确订阅额度。
- **Settings**：自主权限、日程、候选范围、事件日历和通知等常用表单在前，完整配置收进高级区。保留版本校验、预览、密码验证、权限收紧即时生效和放宽冷静期；新增字段必须纳入相同保护，不能通过普通表单形成旁路。
- **通知**：保留自主决策理由摘要、人工例外和系统异常；成交事实由 Robinhood 通知。复用现有条件采集、审计与投递去重，不把每次正常轮询、相同观望结果或同一订单每个状态都作为新的紧急推送。

## 9. 最小接口、数据与兼容调整

接口扩展服务于上述账户绑定与事实展示；继续使用薄 API 和现有 service 层，不为每个导航建立独立后端。

| 能力 | 最小调整 | 不变的边界 |
| --- | --- | --- |
| 有效权限 | 扩展现有配置读取结果，返回账户绑定、动作级授权与限制、版本、撤回状态、阻断原因及待生效变更 | 同一确定性计算用于预检／执行；授权状态不代替下单前实时检查；写入沿用 `/config/preview` 与 `/config/changes` |
| 账户语境 | Advisor 请求、会话、任务和结果增加 `personal`／`agentic` 范围；personal 明确全部个人账户或指定账户 | `account_id` 由服务端校验，不接受模型自报权限；会话范围固定，跨侧不复用上下文 |
| 按需组合复查 | 现有 `/advisor/jobs` 增加 `portfolio_review` 类型，返回优先事项、理由、引用、缺失信息与时间 | 只读、不创建可批准提案；页面加载与快照刷新不启动此任务 |
| Agentic 解释与重新研究 | 解释使用账户绑定的只读上下文；显式操作卡调用现有研究提交服务，绑定 `micro_live` 与用户请求去重标识 | 不新增订单服务；研究模型无执行工具；检查已有持仓／候选身份与开仓权限时分别处理 |
| 研究记录 | 现有研究列表支持账户过滤；工件补充账户范围、任务类型、路线／技能／模型版本、快照与事实截至时间 | 同一报告供多个页面引用；旧记录缺失的版本／时间标为未知，不猜测归属 |
| 当前待办 | 复用现有问题采集规则，输出稳定标识、账户范围、严重性、是否需要人工、原因及处理链接 | 从未解决状态生成；不依赖推送已发送或历史事件存在与否 |
| 历史与评估 | 审计增加必要的账户／任务关联；评估按账户／研究范围汇总，并增加研究路线指标 | 沿用原 SQLite、工件和审计源，不建立第二套账本或模型质量数据库 |

兼容要求：

- 历史个人会话按原 personal 用途保留；缺账户信息的历史报告标为旧记录／范围未指定，不自动归入 Agentic 或赋予执行资格。查询只将归属明确且符合当前语境的记录放入模型上下文。
- 同一标的可以存在多个账户的不同建议；摘要按账户与用途选择最新有效结果，不能只按 ticker 或文件修改时间覆盖。
- 个人持仓复查与未持有候选研究分别校验；不能因个人任务带 `account_id` 就要求所有候选必须已持有。
- 研究／刷新请求复用现有 request id 和持久队列去重。公共事实复用需遵守数据时点与来源范围，不能复用已过期事实形成新交易结论。
- 导航白名单支持新增账户参数；旧 ticker-only 入口不直接发起研究，先引导选择明确语境。旧研究记录深链仍可打开。
- 默认值只用于普通入口，不覆盖已打开报告、持仓深链或现有会话语境。账户切换、语言切换和晚到的异步响应不得改换任务目标。
- 历史评估及研究工件保留；数据结构扩展通过现有状态工具和受测迁移完成，不手工修改生产账本。

## 10. 实施顺序与验收

以下是未来实施顺序，本次只交付计划。新增账户与界面工作已超出原版仅后端的工期估算，因此不沿用原来的天数作为本版承诺。页面重组不以新供应商可用为前提，功能展示以实际后端状态为准。

| 阶段 | 交付 | 验收／停止条件 |
| --- | --- | --- |
| P0：核实与定界 | 实际能力清单、部署版本核对、有效权限矩阵、重复功能清单、账户及评估范围核查 | 每项标明可调用／仅界面／不可用／未核实；不改 live 配置；记录个人深链、状态口径和测试隔离问题 |

P1 是独立的研究质量试验；P2a 使用已通过验证的路线，未通过时继续使用现有路线。前端中的资料编辑、布局和只读展示可先完成，但自主状态、个人复查和评估等依赖后端的部分必须随对应接口验收后发布。

影子模式必须使用隔离的模拟状态／订单通道。不能让待比较方案生成生产可批准提案，也不能用生产账本模拟成交。

技术验收：所有下单经过 `service/approvals.py`；本账户与研究运行时无法访问订单能力；权限收紧立即生效；重启／超时不重复下单；订单不确定状态持续对账；报价、证据和授权过期可确定性阻断。

界面与接口验收：

- Portfolio 默认 Agentic，Assistant 默认我的账户，Research 从 More 默认 Agentic；带账户的深链、前进／返回及页面重载保持正确语境。
- 多个个人账户、相同 ticker 的不同建议、未持有候选、缺失账户和部分覆盖都不串用资金或研究结果；个人路径无法创建可批准提案。
- Agentic 持仓市值使用真实 API 字段；缺数不变零，建议状态不等于执行状态，资产／报价／分析时间独立。
- 页面加载与账户刷新不调用 AI；显式组合复查、完整研究和 Agentic 重新研究分别去重。重复点击、请求超时及晚到响应不创建重复任务或跨账户结果。
- Home 区分服务健康与自主权限、正常自动排队与人工审批；问题恢复后退出待办，接口不可读不显示“无需处理”。后台心跳不替代实际核对结果。
- More 审批入口仅随真实人工事项出现；权限、Risk 与执行判断一致；权限放宽仍需原审阅和冷静期，人工审批不能穿透硬限制。
- Demo、Agentic、个人建议的评估归属正确；质量指标无数据时明确缺失，不以模型自评或不匹配案例进行排名。
- Research 移除通用表单前，Portfolio／Assistant 替代入口及旧链接迁移通过；Lab 只展示实际任务过程，前端新文案中英文齐全。

研究验收与投资验收分开。新流程先比较错误、耗时、额度和修订量；上线后继续现有前向评估、同现金流基准和版本漂移记录，计入不交易、拒绝、失败及交易成本。短期观察或最低样本天数不证明稳定超额收益。

部署仍使用不可变 release；发布前跑 `deploy/checks.sh`，手动停止／重启前跑现有 `--fail-on-unsettled` guard。开发和影子测试不在 live `config/` 上试改权限；启用前展示参数差异及回退方式。
